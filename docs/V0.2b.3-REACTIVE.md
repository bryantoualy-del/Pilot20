# V0.2b.3a — Reactive core

Base: main acecbe915fbfa393188795928e9e069745e0dfcd; PRs #3 and #4 verified merged. This is the first of three dependent sub-lots. It extends the existing execute/validate/snapshot/receipt/repository path. There is no alternate combat executor.

## Executable API

Pinned mechanical actor definitions may carry `rules` (version 1). A rule reuses Trigger v1 and creates Decision v2, extending Decision v1 with `ruleId` and `phase`. ReactionWindow v1 refers to exactly one pending decision and its event/phase; Continuation v1 is JSON (`plan`, including the activated ability and supplied command/dice), not a closure. `pendingDecisions(state)` returns copies. `respondDecision` requires actorId, decisionId, decisionRevision, expectedRevision, choice (`accept`/`decline`), and optionId when accepted. Acceptance checks conditions, action and resource availability again. Costs and continuation execute in the same transaction. Refusal is always possible with current revision; it has no cost. Resume is automatic and atomic; an explicit second resume is rejected.

Order: validate/pay activation → cast window → attack roll (supplied deterministic dice) → after-roll choices → before-hit window and AC reevaluation → after-hit choices → before-damage interception → final consequences → after-damage window. The provisional roll is not returned with an after-roll decision. Only the caller/MJ controls whether it has announced the result. Before-roll choices and standalone start/end-turn reaction windows are represented by Trigger contracts but not yet executable. Saves currently resolve as part of final consequences, not a deferred after-save window.

One event is active at a time; its source, targets and all actors with rules are locked. Unrelated concentration saves are explicitly allowed. Actions, movement, corrections and turn transitions remain dependent because they can change initiative, eligibility, global spell restrictions or damage order. This conservative allowlist prevents deadlocks: refuse or undo the latest transaction to recover. Manual adjudication retains its pre-existing global lock. No timers.

Rules are selected in ascending priority, then actor ID, then rule ID (stable lexical order). Only one decision is exposed at a time; after it closes, eligibility and resources are evaluated before exposing the next. Previously offered rules cannot reopen in the same event. This is an explicit local sequencing policy, not a claim that official reactions are simultaneous. Trigger scope `ally` requires a future explicit allegiance model and is currently not automated.

Every response uses both session revision and decision revision. Undo restores the complete game, including pending event and resources; pending decision revisions are rebased to invalidate old responses. Immutable receipts survive undo. Replaying an undone command returns its old receipt without reapplying anything. A new deliberate response needs a new command ID and current decision version. Undo is latest-transaction only, as before. A declaration can be undone once responses are undone. No history/receipt mutation is introduced.

Closed interpreter operations: event adjustment, temporary effect, additional damage, cancellation and slot-level/ability-check interruption. Unknown operations fail validation. Reaction spells currently require an explicit externally validated `reactionSpellUnopposed` fact: nested reaction spells are refused, never silently approximated. All spatial/perceptive conditions are explicit actor-scoped facts; absence does not mean true. The engine does not determine geometry, components or spell perception.

## Safety and limits

At most 50 rules per actor, 30 options per rule, 200 decisions per event, 100 actors, one active continuation. No operation dispatches a recursive event, so no reaction cycles or orphan continuation queue. Completed event state replaces the previous event on the next declaration. Entitlement stores only the latest turn per actor/rule, not an ever-growing turn list. Mechanical IDs and command IDs must fit domain bounds (reactive declaration IDs ≤65 characters). Runtime validators enforce referential integrity as well as JSON structure.

Snapshots and receipts remain unbounded over session lifetime; snapshots copy the bounded continuation and actors, so long-session cost remains proportional to retained history and validation traverses it. Existing split IndexedDB repository deduplicates pinned definitions but not continuation plans. No Safari/iPad timing or memory measurements have been made. No performance claims; archive/export and start a fresh session before reaching the existing 10 MB JSON limit. Safe future compaction must preserve idempotence tombstones and undo boundaries.

Encounter mode still requires Encounter authority before any mutation, including decision responses. No transport, UI, account, cloud, deployment, historic Companion or Encounter changes.

## Scope of this PR

Executable: generic deferred decisions, ordered windows for ability resolution, exactly-once conditional costs, generic event modifiers, refusal, JSON/IndexedDB resume and undo. Represented: unimplemented Trigger moments. Manual: existing declareManual/resolveManual. Deferred to 3b: official reaction/post-hit profiles. Deferred to 3c: transfers, Rage, casting modifiers, final demonstration and coverage. No class/spell completeness claim.

# V0.2b.3b — Combat reactions

Depends on 3a (PR #5). `srd-reactions.js` produces pinned rule data for Uncanny Dodge, Shield, Counterspell, Sneak Attack and Divine Smite. The scheduler has no class/character name branch. Definition `combat.traits` describes weapon melee/ranged/finesse/Strength properties. External actor-scoped facts validate perception, adjacency, creature type and spell prerequisites; absence does not invent eligibility. Rule conditions are bounded all/any trees, not JavaScript.

Shield's AC applies to the triggering hit and expires on the caster's next start. `magicMissile` semantic tag plus `negatedByEffects:['shield']` makes that spell's declared consequences ineffective on protected targets (including the triggering spell). Other targets are unaffected. Spell access/components are explicitly validated externally; the builder alone does not make an unknown spell available. Existing concentration is retained.

Counterspell takes an actual standard or pact slot; a higher target spell uses a deterministic d20 + casting ability modifier versus 10 + its actual slot level. Both original and reaction costs remain spent on interruption/failure. Nested spell reactions require manual adjudication: acceptance is blocked without an external `reactionSpellUnopposed:true` attestation. Same-turn bonus-action spell restrictions use the existing per-turn cast ledger. Counterspelling a Counterspell is deliberately not advertised executable.

Sneak Attack records the actual session turn ID, not a round. Its dice inherit the weapon damage type and double on critical. An eligible adjacent enemy includes its hostility to the target, distance and non-incapacitation, all covered by `adjacentEnemyEligible`; disadvantage on the actual roll blocks it. Divine Smite checks melee weapon hit, spends the chosen slot only on acceptance, caps normal/fiend-undead dice at 5/6 and doubles dice on critical. Creature type must be explicitly true or false; missing classification refuses this automation.

Damage results expose rawDamage, modifiedDamage, defendedDamage, typed components (raw/afterSave/afterModifiers/afterDefenses), actual damage, tempLost and hpLost. Order: confirmed hit → critical dice and additional typed dice → conditional damage modifiers → save reduction → interception → immunity/resistance/vulnerability → temporary HP → actual HP → concentration using the damage taken (including absorption) → cleanup/elimination. Typed amounts are grouped before rounding; each typed subtotal rounds down at each halving step. Mixed-type damage sharing a reduction uses this explicit local policy; disputed allocations need manual adjudication. Definitive Encounter/manual outcomes bypass defenses and are never recalculated.

Executable bounded mechanics are not complete official spells: geometry, spell components, casting eligibility and target classification are external validation. Death saving throws, instant death and complete condition semantics remain outside this PR. Armour of Agathys retaliation and opportunity detection remain manual; the ordinary reaction attack command can be used only after external opportunity validation. No original Companion implementation imported.

# V0.2b.3c — conditional mechanics and current API

The current authoritative scope and limitations are in [V0.2b.3-VALIDATION.md](V0.2b.3-VALIDATION.md); the 3a/3b descriptions above record those independent sub-lots. Runtime/event v2 supersedes v1 through explicit migration. Versioned schemas: `reactive-rules-v2.schema.json`, `conditional-rules-v1.schema.json` plus additive character/session/profile schemas.

`respondDecision` can include `validatedFacts:{attackerVisible:true}` only when that external fact was requested in the pending decision's `validationRequired`. The declaration's existing facts are retained, and requested attestations are persisted separately. The decline command has no validation prerequisite. Caller/MJ must not reveal a roll's result before the after-roll window closes; deterministic input dice do not themselves authorize late modifier selection.

`useAbility` accepts `castingModifiers:['quickened']` or `['heightened']` and `modifierTargets:{heightened:targetId}`. IDs refer to pinned declarative modifier data, not hard-coded class dispatch. Original timing/target requirements and generic resource costs remain authoritative. `endStance` costs the stance's bonus action on its owner's turn. `setUnconscious` explicitly distinguishes loss of consciousness from generic conscious incapacity; zero HP also ends the stance.

Transferred resources live in optional `advanced.tokens`, sustained stances in `advanced.stance`, hostile/damage sustain evidence in `advanced.activity`. The transfer profile uses a stack key, die size, duration and externally validated requirements. The `roll` profile can represent a declared ability check/save with explicit statistic/DC, while ordinary attack and multi-target spell saving rolls use the same after-roll choice scheduler. A concentration save currently uses its original command and needs manual inspiration adjudication.

Standalone turn boundaries, time outside initiative, automatic geometry and nested reaction spells remain limited as documented. No whole-class or whole-spell automation is implied by these generic data contracts.
