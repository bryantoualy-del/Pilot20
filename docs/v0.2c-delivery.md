## Review before freezing the V0.3 contract

The implemented gate is now **review-ready-with-documented-manual-scopes**. The first draft’s concrete blockers have been addressed: explicit nested selections, optional verified learning/replacement history, class-specific preparation, actual-level slot-free casts, manual resource costs and safe calendar recovery. Manual geometry/effects, calendar adjudication, authorized expansion data and imports without history remain explicit qualifications. A green suite is not a claim of complete rulebook automation. Review the documented manual workflows before accepting the release or freezing V0.3 contracts.

Concrete V0.3 preparation: expose `issues` and `manualRequirements` together, require explicit ancestry/background, use one shared resolver for Guided/Rapid/Expert modes, keep authored templates distinct from automatic choices, and build the single vertical path “create → save → open Companion → local combat”. Do not expand backend automation indefinitely; decide and expose acceptable manual workflows first. No V0.3 implementation is included here.


## Follow-up implementation notes

`advancement.js` provides the level-up audit and versioned complete plan. Existing character v2 choice notes retain compact deltas, so library/JSON persistence is reused. Casting schemas gain optional contribution/start-level policies and a slot-free policy; old defaults and saves remain supported. `engine.js` is unchanged; the small changes to `model.js` and `rules/combat.js` make real-level free/charged spells legal and preserve bonus-action restrictions. The former level-zero Arcanum workaround is removed. Manual Counterspell interaction with manually declared spells remains adjudicated.

Tasha/Xanathar private PDFs have now been reviewed locally for representative architectural requirements; the compatibility matrix states the scope and limits. No protected expansion text, imagery or official expansion class corpus is published.
