# V0.3.1 — Validation et limites

**Livraison proposée en PR dépendante de #13, sans fusion ni déploiement. Safari physique reste à valider.**

## Périmètre

Huit étapes stables : Race → Classe & niveau → Capacités de classe → Historique → Caractéristiques → Maîtrises → Sorts & équipement → Finalisation. Les trois modes partagent le même plan et les mêmes étapes. Le multiclassage reste soumis à l’option de campagne et au mode Expert.

Les décisions proviennent de `resolveProgression`. `resolveOrigins` est appelé par ce moteur et le constructeur. Les PV réutilisent la même politique extraite du calcul dérivé et du constructeur : aucune règle de classe n’est réimplémentée dans le rendu.

- Neuf races SRD ; sous-races : nain des collines, haut-elfe, halfelin pied-léger, gnome des roches. Bonus, vitesse, langues, maîtrises, résistances et robustesse naine calculés. Effets situationnels et sorts raciaux explicitement manuels.
- Acolyte SRD 2014 : compétences, deux langues, aptitude et équipement ; remplacement explicite des compétences en doublon. Les autres historiques officiels nécessitent un pack privé autorisé. Parcours personnalisé conservé avec revue MJ.
- Tableau standard, achat de points, 4d6 en gardant les trois meilleurs, saisie manuelle. Provenance Base/Race/Améliorations/Finale, modificateurs et PV moyens affichés. Préparation et prérequis revalidés après changement.
- Douze profils d’armure et trente-six profils d’arme SRD ; maîtrise et caractéristique d’attaque dérivées. Quantités, budget, packs de départ, propriétés spéciales et autres objets restent à vérifier avec le MJ. Le filet n’est pas représenté par un faux profil de dégâts.
- Lexique de sorts centralisé. Les labels français existants sont conservés ; les noms sans traduction vérifiée affichent « traduction FR indisponible ». Les textes de référence non traduits sont signalés, sans inventer de traduction officielle.
- Autosauvegarde, date/étape sur les cartes, sortie/reprise et filtre « En cours ». IndexedDB, transactions, révisions et exports existants conservés.
- Une décision invalide est signalée et conservée. L’action explicite de mise à part permet de revalider un niveau inférieur. Chaque décision reste restaurable ; un choix actuel remplacé par une restauration est lui-même conservé. Aucun effet inaccessible n’est appliqué silencieusement.

## Défilement et interactions

Viewport 1180 × 820. Hauteur du document entier en pixels CSS. Après correction, les décisions terminées sont repliées ; rouvrir une liste augmente volontairement sa hauteur. Les listes ouvertes sont paginées, avec un seul défilement vertical du document.

| Écran | Avant | Après |
| --- | ---: | ---: |
| Classe du guerrier | 1173 px | 935 px |
| Capacités du barde 10 | 2158 px | 822 px |
| Sorts du barde 10 | 2114 px | 820 px |

Les fichiers `before-metrics.json` et `after-metrics.json` font foi. Ces mesures ne sont ni des temps ni des gestes humains ; deux pixels de dépassement ne représentent pas un écran supplémentaire.

Comparaison à référence constante : même guerrier personnalisé 1, mêmes valeurs, deux compétences d’historique, deux de classe, Défense, mailles et bouclier, sans suggestions. **23 → 21 interactions sémantiques**, **9 → 7 changements d’écran**. Une saisie, une sélection, une case ou un clic vaut une interaction ; blur, attentes et captures sont exclus. Réduction modeste d’interactions : le gain principal concerne la lecture et le défilement. Le nouveau catalogue d’origines n’est pas utilisé pour gonfler cette comparaison.

## Compatibilité et couverture

Personnages v2 et brouillons v1 préservés. Les anciens scores restent finaux ; l’utilisateur peut explicitement les traiter comme des bases. Les anciens noms d’étape sont redirigés sans supprimer les choix. Les décisions mises à part sont exportées avec le brouillon.

Source publique : [SRD 5.1 anglais CC BY 4.0](https://media.wizards.com/2023/downloads/dnd/SRD_CC_v5.1.pdf). Les résumés français sont des libellés de présentation, sans revendication de traduction officielle intégrale. Attribution existante conservée. Aucun PDF, OCR ou pack privé officiel ajouté à git.

La personnalisation d’origine exige des options de pack installées et activées indépendamment ; ses contrats sont testés avec des données originales. Aucun Artificier/infusion officiel complet, aucune couverture exhaustive Xanathar/Tasha et aucune automatisation totale des traits raciaux ne sont annoncés.

Le benchmark étudie les pages publiques et guides accessibles, sans prétendre avoir testé quatre sessions connectées sur tablette. Les acquisitions/remplacements anciens utilisent la validation par instantanés lorsqu’ils existent, sinon une revue MJ. Un compteur de choix complet ne démontre pas à lui seul leur légalité historique.

## Reproduction

```sh
npm ci
npm test
npm run coverage:check
npm run coverage:catalog:check
npm run build:web
npx playwright install chromium
npm run test:e2e
npm run dev
```

Un Chromium préinstallé peut être fourni avec `PILOT20_CHROMIUM`. Les deux suites navigateur sont exécutées par la CI. Pour la comparaison d’interactions, construire séparément la tête V0.3 `7839ebc3`, puis exécuter `PILOT20_BASELINE_ROOT=/chemin/vers/checkout-v03 node e2e/benchmark-ux.mjs`.

La validation finale de livraison attend la revue des dépendances, la CI de la nouvelle tête et le test Safari physique. Aucune fusion ni publication automatique.
