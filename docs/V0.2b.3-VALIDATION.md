## Executable contracts and scope

The existing `execute`, Combat Session, receipts, undo history and split IndexedDB repository are extended; no parallel combat engine. Character v2 gains optional `reactiveRules` and `castingModifiers`, pinned by derive/createCombat. New conditional profile properties remain declarative. There is no character-name dispatch in the executor.

Reactive runtime/event v2 adds per-target provisional saving totals and external validations to the 3a/3b v1 format. `migrate`/`deserialize` explicitly upgrade v1 current state and undo snapshots on copies, without changing receipts. `schemas/reactive-rules-v1.schema.json` is preserved; v2 is separate. Decision v2 remains additive to Decision v1; missing `validationRequired` is accepted on earlier decisions. Conditional profile data has its own v1 schema. Schema validation and domain reference checks are complementary.

An unknown external prerequisite opens a decision listing `validationRequired`, not a silent skipped reaction. Accept with current revisions and `validatedFacts` for the requested external keys, or refuse. Previously pinned facts cannot be overwritten by a response. A refusal needs no external attestation and spends nothing. Original plans are prevalidated on an isolated game snapshot before pausing, so malformed original dice/effects cannot strand a refusal; response effects are checked on the same interpreter before committing/resuming. These validation previews never become combat results.

- Shield: reaction slot chosen once, +5 AC including the triggering attack, next-caster-start expiry, Magic Missile negation on protected targets, existing concentration preserved. Spell access/components validated externally.
- Uncanny Dodge: visible attacker attestation, one hit/one reaction, halving before defenses, actual damage drives temporary HP and concentration.
- Counterspell: externally validated perceived casting/range/access, ordinary/pact slot, actual original slot level, automatic cancellation or casting ability d20 vs 10 + target level. Costs stay spent on a failed check. Nested reaction spells are explicitly blocked unless the caller attests no counter-reaction; genuine Counterspell chains remain manual.
- Sneak Attack: finesse/ranged weapon, actual advantage or validated eligible adjacent enemy without disadvantage; entitlement by session turn ID; no spend on decline/miss; all extra dice doubled on critical.
- Divine Smite: melee weapon hit, optional slot selected after hit; standard/pact resources; normal/fiend-undead 5/6d8 cap; dice doubled on critical; explicit creature-type validation.
- Bardic Inspiration: bonus action/source uses are distinct from the recipient token and later choice. One token per stack key, level-scaled d6/d8/d10/d12, 100 source-turn logical expiry; recipient can spend after attack/save/declared ability-check roll before result. Multiple-target saves remain separate; refusal retains token. Concentration-save-specific inspiration windows are not integrated yet; use adjudication rather than pretending that case is automated.
- Rage: bonus action/source use; 10-start maximum duration; conditional Strength melee weapon damage, physical resistances, Strength checks/saves advantage, no spells/concentration; hostile attacks or damage since previous turn sustain it, level-15 persistent exception, unconscious/zero-HP end, voluntary bonus-action end. Heavy armor eligibility must be attested; changing equipment mid-stance is outside this model. Frénésie is separate and not fabricated. Level-20 unlimited activation must be expressed with a no-cost data profile; the level-10 fixture does not claim to implement that character progression.
- Metamagic: changes a casting plan before costs/rolls resolve; 2-point action-to-bonus conversion and 3-point one-target first-save disadvantage, normal advantage cancellation and 2014 bonus spell restrictions in both orders; exclusive metamagic group prevents unsupported combinations. No class branches or duplicated spell effects.

## Deferred and manual boundaries

This is substantial V0.2b.3 delivery, **not unconditional completion of every acceptance item**. Before-roll and standalone turn-start/turn-end/movement-triggered decision windows remain contract-only; turn boundaries do execute duration/sustain cleanup. Full spatial opportunity detection, Counterspell chains, concentration-save inspiration, repeated-save spell effects beyond the supported first save, Agathys retaliation, transformations, summons, zones and auras are not automated. Unsupported operations fail closed; available manual abilities use the existing declareManual/resolveManual workflow with reasons and authoritative final values. Glamour/Éloquence-specific rules are not redistributed or represented as automated.

Definitive Encounter results must use the final-outcome manual boundary, not the raw `damage` intent (which applies local defenses). Encounter authority remains mandatory for mutation; WebSocket transport and live reconciliation are not implemented. Replaying a receipt never applies its returned result to the state a second time.

Unspecified reaction order is deterministic priority/actor/rule ordering and must be reviewed by the MJ for competing effects. Typed damage aggregates and rounds down at each typed save/interception/defense step; ambiguous mixed-type reduction allocation stays explicitly adjudicated. Death-save/instant-death rules and comprehensive official condition semantics remain outside scope.

## Performance and product implications

One active event, bounded rules/options/windows and current-turn entitlement prevent unbounded continuation queues and recursion. Closed events are replaced; immutable historical snapshots/receipts are still retained. The repository deduplicates actor definitions, not every continuation payload. Full-state cloning, JSON validation and history validation scale with retained session history; the five-round synthetic integration test already takes tens of seconds locally for the entire script, so this architecture requires performance work before claiming iPad production readiness. This is not an iPad latency benchmark. No Safari/memory/long-session measurements are invented.

Future Companion can show pending choices, requested validations and legal resource options without callbacks. Future Encounter can own decisions and final results using the same IDs/revisions; authority is not transferred implicitly. No UI, websocket or catalogue rollout is part of this work.

V0.2c preparation: usable foundation for **incremental** SRD catalogue compilation, with whole-item coverage gates. Review/migrate these three lots first. Resolve remaining required trigger families and performance/IndexedDB constraints before broad automation; do not bulk-enable twelve classes or all spells from fixture success. V0.2c has not started.
