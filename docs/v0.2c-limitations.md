# Known limits and release assessment

This branch delivers a substantial V0.2c implementation, but **does not assert that every acceptance criterion is fully complete**. The report keeps a partial review gate rather than claiming an exhaustive universal character builder.

- All 12 base classes have 20 acquisition rows; all 12 SRD subclasses and 319 SRD spell descriptions are present. Numeric tables and current-build choices are tested. An independently extracted spell-list manifest is compared by name and class.
- Nested choices now include Hunter branches, favored enemies/terrains, wizard mastery/signature, Land bonus cantrip, Tome cantrips and Ancient Secrets rituals. Remaining language/humanoid-race/tool detail is exposed as `manualRequirements`. Not every nested rule is a fully validated selection graph.
- Per-level wizard spellbook acquisition and historical spell replacement are not validated from level-up history. Current maximum level and access are checked; importing a high-level build still requires review. Background proficiencies are not added automatically. The ancestry placeholder must be replaced in V0.3.
- Spell Mastery, Signature Spells, at-will invocations, ritual casting, resource conversions, domain feature pools, seven-day Divine Intervention recovery, subclass counters and complex recharge schedules require manual resolution/tracking. Selecting a mastery/signature spell does not silently make it slot-free in combat. Long casting times and long concentration durations are GM-managed.
- Class reference text and spell descriptions are authoritative English SRD extracts with normalized PDF formatting; per-feature descriptions are conveniences, not a substitute for that reference. Feature inventory percentages are withheld because the total number of nested official feature entries is not independently established.
- Every whole spell/feature is manual or partial. Zero entries claim whole-effect automation. Existing reaction/stance/transfer/casting adapters are reused. Simple numerical spells, Haste, healing, fighter resources, rogue/paladin reactions, Rage and bardic transfer execute only in the documented scope. Externally supplied eligibility facts must be trusted authoritative decisions, not unchecked client assertions.
- Generic manual feature buttons intentionally leave action economy and outcomes to the GM; they do not spend every feature-specific counter automatically. Wild Shape, summons, terrain, auras and utility/narrative consequences remain manual.
- Mystic Arcanum spends its separate once-per-long-rest resource through a manual slot-free declaration; the underlying spell-cast profile is level zero to avoid spending a pact/standard slot. Its actual fixed level is in catalogue/choice metadata and declaration requirements. Counterspell interaction with this declaration therefore requires manual adjudication.
- Generic half-caster multiclass math must not be used for Artificer round-up contribution. The optional thirteenth class is model capacity only, not official implemented content.
- No iPad/browser performance or visual UX claim. Benchmarks cover Node on the reported host, with module parse excluded from warm index timing.

Before calling the whole V0.2c release complete, review these manual obligations and decide which are acceptable manual workflows for V0.3 versus which need normalized choices. Do not start V0.3 or freeze its contracts solely because the test suite is green. No merge or deployment is authorized by this branch.
