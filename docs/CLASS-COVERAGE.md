# Twelve-class architecture audit — D&D 2014

Scope: SRD 5.1, levels 1–20, its twelve base classes and one open subclass each. This is an architectural inventory, not a complete class implementation or progression catalogue. Synthetic fixtures pin level choices; the engine does not infer features from a class name. Reference: [official SRD 5.1, CC BY 4.0](https://www.dndbeyond.com/attachments/39j2li89/SRD5.1-CCBY4.0License.pdf), Classes, Multiclassing and Spellcasting sections. No 2024 rules are enabled.

All classes require proficiency/ASI progression, level-ordered HP, feature grants, equipment legality, resources, rest and optional multiclass validation. V0.2 calculates supplied progressions, spell-slot tables, saves, attacks and AC. It does **not** resolve the full official feature tables or subclass choices. A valid structural fixture is not proof of a fully legal official build.

## Multiclass prerequisites and grants

Apply both the old and new class prerequisites: Barbarian STR13; Bard CHA13; Cleric WIS13; Druid WIS13; Fighter STR13 **or** DEX13; Monk DEX13 **and** WIS13; Paladin STR13 **and** CHA13; Ranger DEX13 **and** WIS13; Rogue DEX13; Sorcerer CHA13; Warlock CHA13; Wizard INT13. Existing generic AND/OR score prerequisites can represent these. V0.2c must bind them to level-up choices and separate starting proficiencies from multiclass proficiency grants. Extra Attack does not stack across classes. Pact Magic and ordinary Spellcasting remain separate pools; known/prepared level eligibility remains per class.

## Progression and intervention boundary

V0.2c must deliver versioned per-level grants, ASI/feat and subclass choices, known/prepared counts, spellbook entries, ritual exceptions and unlock prerequisites. The six added fixtures exercise the common contracts at several levels; they intentionally do not claim full feature tables or all official build choices. Player/MJ intervention is required for line of sight, range, cover, hostile context, illusion adjudication, form eligibility and area membership until corresponding primitives exist. Subclasses remain data with unsupported behavior blocked; no class-name branches belong in the engine.
