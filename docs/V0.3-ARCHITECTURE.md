# V0.3 architecture

Native ES modules are split into application shell, DOM helpers, centralized FR/EN strings, editor and local Companion. No UI rule calculations: progression resolves choices, campaign compilation constructs characters and derive calculates statistics. JSON packs cannot provide executable code.

Existing IndexedDB `pilot20` stores are reused. Character records and preferences remain owned by characterLibrary. Incomplete creator drafts use versioned meta records with compare-and-swap revisions; campaign parameters and packs keep the #9 repository. Exports include both the character and its creation plan, so lossless editing survives export/import. Imported values are rendered with textContent/DOM nodes, never evaluated or inserted as HTML.

Changes are serialized before navigation and stamped with the last loaded revision. Another tab's update causes a conflict rather than overwriting. Storage/quota failures are surfaced. Portraits are resized to a bounded data image before saving; no remote image is required.
