# V0.3.2 — Validation

Branche dédiée depuis `main` `7bc6ec6` (V0.3.1 intégrée). PR de revue, sans fusion ni déploiement. Le détail des dépendances est dans `V0.3.2-UX-ARCHITECTURE.md`.

## Exécution locale

- Baseline : 369 tests Node réussis.
- V0.3.2 : **376/376 tests Node**, dont sept tests supplémentaires (simulation, indétermination, barde/magicien 10, conservation de sous-classe, diagnostics, filtres, intégrité SHA-256 des assets).
- Contrôles `coverage:check`, `coverage:catalog:check`, démonstrations moteur, personnage, combat, catalogue et progression exécutés avec succès.
- Navigateurs : **29/29 scénarios réussis** (14 hérités V0.3, 8 hérités V0.3.1 et 7 nouveaux), zéro erreur de page ; suites héritées et nouvelle suite `builder-v032.mjs`. Résultats complets dans les artefacts CI et `screenshots/v032/measurements.json` ; Chromium local **131.0.6778.33**. La CI utilise le navigateur Playwright courant. La tentative d'installation locale de Chromium 149 renvoyait une archive vide ; la première série locale a donc utilisé le headless shell 131 téléchargé depuis la distribution officielle Playwright. Après correction de la synchronisation des mesures, les sept nouveaux scénarios ont aussi été répétés avec succès sous **Chromium 149.0.7827.55 local**, obtenu depuis la distribution officielle Chrome for Testing.

La première passe CI Chromium 149 a mesuré deux boutons à 0×0 lors du retour répété sur une même étape : le test pouvait lire l’ancien DOM détaché pendant le rendu asynchrone. Le helper attend désormais le remplacement réel du titre avant toute mesure, y compris lorsque son texte reste identique. Les minima physiques/logiques et le non-rétrécissement des actions sont également explicites. Le seuil tactile reste de 44 px et les échecs rapportent viewport/dimensions.

## Benchmark à scénario constant

`e2e/benchmark-v032.mjs` rejoue exactement un même guerrier personnalisé niveau 1 sur les deux versions : scores initiaux identiques, Défense, Athlétisme/Perception, historique Religion/Médecine, mailles/bouclier ; aucune suggestion. Même viewport 1180×820 et même Chromium. Une saisie, un clic, une case ou un select compte pour une interaction ; blur, attentes et captures sont exclus. Les changements incluent ouverture du créateur et du Companion.

Fichiers bruts : `screenshots/v032/benchmark-v031.json` et `benchmark-v032.json`. La V0.3.2 **ne démontre pas de gain d'interactions ou de défilement global** sur ce scénario. Les nouvelles capacités d'exploration/simulation et le détail de finalisation occupent davantage d'espace ; la première version du rail, trop haute, a été compactée pendant validation. Cette limite est conservée dans le bilan, pas masquée par un scénario différent.

Les durées brutes du replay automatisé figurent dans les JSON, mais un passage unique n'établit pas une différence significative de vitesse. Les mesures d'ouverture des comparateurs et de simulation sont dans `measurements.json`. Elles incluent le clic Playwright et le rendu : ce ne sont pas des temps moteur isolés, ni une promesse sur iPhone. Aucune mesure humaine de compréhension, temps de création ou temps pour retrouver une capacité n'est inventée.

Stabilité : égalité profonde des brouillons persistés avant/après comparaison et annulation d'aperçu, égalité des choix après fermeture/réouverture réelle du contexte navigateur, reprise après changement de niveau et réactivation de source. Les timestamps/révisions ne sont modifiés que lors d'une action explicitement sauvegardée.

## Limites et revue restante

**Safari/iPad Air 5/iPhone physiques, clavier virtuel réel, VoiceOver et sessions humaines non testés.** Protocole détaillé dans `V0.3.2-RESPONSIVE.md`. Les comportements VisualViewport/safe areas sont implémentés ; leur présence ne constitue pas une validation physique.

Les limites de contenu et de moteur antérieures restent applicables : packs officiels privés non distribués, traduction intégrale des libellés non revendiquée, effets manuels et automatisation partielle signalés, propriétés spéciales/budget d'équipement et historique d'acquisition sans instantanés à revoir avec le MJ. Aucune règle 2024, nouveau moteur, service IA, cloud ou export PDF avancé introduit.

Le comparateur ne présente que des candidats réellement installés et activés. Les métadonnées éditoriales de style des sous-classes restent limitées aux informations présentes dans les packs ; aucune recommandation officielle Glamour/Éloquence inventée. Les comparaisons gardent toutes les informations mécaniques utiles en rubriques, avec davantage de défilement sur téléphone.

## Reproduire

```bash
npm ci
npm test
npm run build:web
npx playwright install chromium
npm run test:e2e
npm run benchmark:ux
```

Pour comparer la baseline : créer un worktree détaché à `7bc6ec6`, y installer les dépendances et exécuter son `scripts/package-web.mjs`, puis lancer depuis cette branche `node e2e/benchmark-v032.mjs v031 /chemin/baseline/dist`. Aucun déploiement n'est nécessaire. `PILOT20_CHROMIUM` permet de préciser un exécutable local ; la CI utilise le navigateur installé par Playwright.
